# 计全支付（Jeepay）项目结构分析

> 报告生成日期：2026年5月26日

---

## 一、项目概述

| 项目 | 信息 |
|------|------|
| **项目名称** | 计全支付（Jeepay） |
| **官网** | https://www.jeequan.com |
| **开源协议** | LGPL-3.0 |
| **技术栈** | Spring Boot 3.3.7 + JDK 17 + MyBatis Plus + Redis + RocketMQ |
| **项目定位** | 面向互联网企业的开源支付系统，支持普通商户模式、服务商模式、聚合支付与多应用接入 |

### 核心功能

- 聚合支付：微信支付、支付宝、云闪付等主流渠道统一接入
- 商户模式：支持普通商户、多渠道服务商、聚合码支付
- 系统架构：运营平台 + 商户平台 + 支付网关三大核心系统

## 二、模块结构

### 2.1 Maven 模块总览

```
jeepay (根项目, groupId: com.jeequan, artifactId: jeepay, version: Final)
├── jeepay-core                   # 核心基础模块（工具类、常量、异常、实体）
├── jeepay-service                # 业务服务层（Mapper、Service 实现）
├── jeepay-payment                # 支付网关（端口 9216）
├── jeepay-merchant               # 商户平台（端口 9218）
├── jeepay-manager                # 运营平台（端口 9217）
├── jeepay-z-codegen              # 代码生成器（独立工具）
└── jeepay-components             # 公共组件聚合
    ├── jeepay-components-mq      # 消息队列组件（RocketMQ / RabbitMQ / ActiveMQ）
    └── jeepay-components-oss     # 文件存储组件（本地存储 / 阿里云 OSS）
```

### 2.2 模块依赖关系

```
jeepay-payment  ────────────────┐
jeepay-merchant ────────────────├──→ jeepay-service ──→ jeepay-core
jeepay-manager  ────────────────┤
                                └──→ jeepay-components-mq
                                └──→ jeepay-components-oss

jeepay-z-codegen (独立工具，无模块依赖)
```

### 2.3 模块详细信息

| 模块 | artifactId | 端口 | 描述 |
|------|-----------|------|------|
| **jeepay-core** | jeepay-core | - | 基础函数库，提供所有模块共用的基础设施 |
| **jeepay-service** | jeepay-service | - | 业务服务层，数据访问与业务逻辑实现 |
| **jeepay-payment** | jeepay-payment | 9216 | 支付统一网关，处理支付/退款/转账/分账 |
| **jeepay-merchant** | jeepay-merchant | 9218 | 商户自助系统，订单查询/支付配置/资金分账 |
| **jeepay-manager** | jeepay-manager | 9217 | 运营管理平台，系统配置/商户管理/权限管理 |
| **jeepay-components-mq** | jeepay-components-mq | - | MQ 组件，支持三种消息队列方案 |
| **jeepay-components-oss** | jeepay-components-oss | - | OSS 组件，文件存储抽象层 |
| **jeepay-z-codegen** | jeepay-z-codegen | - | MyBatis Plus 代码生成器 |

## 十一、架构亮点

1. **多模块分层清晰**：core → service → 应用层，依赖单向，解耦良好
2. **支付渠道可插拔**：通过 `IPaymentService`、`IRefundService` 等接口扩展新渠道
3. **MQ 方案灵活切换**：RocketMQ / RabbitMQ / ActiveMQ 配置即切换
4. **完整 RBAC 权限系统**：运营平台 + 商户平台双系统权限，细粒度控制
5. **支付订单完整生命周期**：支付 → 异步通知 → 分账 → 完成，含重试和过期处理
6. **文件存储抽象**：本地存储 / 阿里云 OSS 轻松切换
7. **一键 Docker 部署**：完整服务栈定义，开箱即用
8. **WebSocket 实时推送**：商户平台实时获取订单状态变化
